# CoursePilot

Расширение Chrome с отдельным планом **50 часов / 25 календарных дней на предмет**. Несколько курсов делят общий бюджет предмета. До четырёх предметов выполняются параллельно в отдельных вкладках; у каждого своя дата начала, очередь и пауза.

## Установка

1. Откройте `chrome://extensions` в Chrome версии 120 или новее.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение» и выберите папку `extension` рядом с этим файлом. Если вы скачали подготовленную папку `dist/coursepilot`, выбирайте её: внутри должен лежать `manifest.json`.
4. Закрепите CoursePilot на панели браузера и нажмите значок. Откроется боковая панель. Полный экран доступен через параметры расширения.
5. Войдите в собственный аккаунт Coursera. Каждый участник устанавливает расширение в своём профиле Chrome.

Расширение не требует установки Node.js для обычного использования. Оно написано на JavaScript с ES-модулями без сторонних библиотек и без этапа сборки.

### Обновление до 0.2.6

Замените файлы в той же папке расширения. На `chrome://extensions` нажмите значок перезагрузки CoursePilot, затем обновите открытые вкладки Coursera. В панели возобновите приостановленный предмет. Не удаляйте расширение: переустановка может удалить локальные настройки и журнал.

В 0.2.6 временная ошибка API и повреждённый формат ответа допускают два дополнительных запроса, то есть максимум три попытки. Паузы — 1,5 и 3 секунды; каждая попытка расходует обычный дневной лимит. Перед повтором заново проверяются предмет, расписание, аккаунт, адрес, модель и ключ. Ошибки авторизации, неверные параметры запроса, отказ модели и обрезание ответа по пределу токенов автоматически не повторяются. Бюджет токенов не увеличивается.

Ошибка запуска, загрузки или декодирования видео допускает два дополнительных повтора через 2 и 4 секунды. Для ошибки источника плеер перезагружает источник, не перематывая ролик к концу. Встроенные необязательные окна `Question` и `Reflect` внутри плеера закрываются только через распознанную кнопку `Skip`; варианты ответов не выбираются, `Submit` не нажимается, запрос ИИ не нужен. После закрытия видео возобновляется. Неработающая кнопка Skip также ограничена двумя дополнительными кликами. Неизвестные окна, CAPTCHA, платежи и другие заявления остаются ручными.

Окно `Ready to submit?` с двумя кнопками `Submit` и `Cancel` подтверждается только после отправки расширением текущей попытки и при включённой автоотправке. Финальный Submit нажимается один раз; защита сохраняется между перезагрузками. Ожидается явный проходной результат, затем разрешён переход дальше. Ошибка ожидания результата не вызывает повторную отправку работы.

Для `Explore: Keep organizations secure` добавлена вводная кнопка `Continue` во внешнем iframe. В манифест добавлено разрешение на сервер этой инфографики на CloudFront, а скрипт внедряется только по точному пути её файла. Обработчик запускается только внутри рабочей вкладки нужного материала, при активном предмете. После открытия экрана с интерактивными метками предмет остаётся на ручном этапе: один Continue не отмечает работу завершённой и не заменяет прохождение инфографики. Произвольные внешние виджеты не поддерживаются.

В 0.2.5 плеер ожидается до двух минут без преждевременной остановки предмета. Видео запускается без звука на скорости 1×, пауза автоматически возобновляется, следующий материал открывается только после события окончания ролика. Буферизация и ожидание загрузки не добавляют время. Зависший запрос запуска отменяется через 15 секунд с повтором через 2 секунды; запрет браузера или ошибка источника показываются отдельно. Чтобы остановить автоматический запуск, приостановите предмет в CoursePilot.

Новые рабочие вкладки сначала создаются пустыми, затем отключается звук и открывается Coursera. При продолжении уже открытая рабочая вкладка также становится беззвучной; посторонние вкладки не меняются. Если выключить звук не удалось, предмет останавливается с пояснением. Распознанное поздравление `Module complete!` закрывается через его кнопку `Close celebration dialog`, после чего досматривается оставшаяся часть видео. Другие неизвестные диалоги автоматически не закрываются.

В 0.2.4 добавлена отдельная настройка «Автоматически отмечать галочку Coursera Honor Code». Она выключена по умолчанию, в том числе после обновления существующей установки. Для работы нужны включённые ИИ, автоотправка тестов и эта настройка. После выбора и проверки ответов обработчик отмечает только единственную именную галочку в распознанном блоке `HonorCodeAgreement` с точным известным заголовком и текстом заявления. Затем ждёт подтверждения формы перед отправкой. Клик ограничен одним на попытку и сохраняется между перезагрузками; изменённое заявление, другой чекбокс, несколько подтверждений, отключение настройки или ошибка сохранения оставляют действие ручным. В Coach эта опция не применяется.

В 0.2.3 исправлено зависание на `view-feedback` после сданного теста. Итоговый блок `AssignmentViewTopBanner` сравнивается с указанным в нём проходным баллом: `Your grade: 100%` при пороге 75% разрешает штатный переход дальше. Прошлая максимальная оценка, отдельный процент в вопросе и отсутствие порога не считаются успехом. Страница результатов не отправляется в ИИ и не запускает новую попытку. Переход после Coach из 0.2.2 подтверждён в установленном расширении: Selenium Coach сменился следующим уроком.

Начиная с 0.2.3 распознаётся также именная галочка `I, …, understand and agree` в Coursera Honor Code. Она не является ответом на вопрос теста. Без отдельного включения новой настройки 0.2.4 виджет ждёт ручного подтверждения, а не повторного запроса ИИ.

В 0.2.2 исправлен переход после реального экрана завершения Coach: распознаются отдельное уведомление `The Dialogue has ended` и отметка `Completed` вне переписки, при отсутствии активного поля ответа. Одного завершения чата без `Completed` недостаточно. Кнопка `Try again` не нажимается, новый запрос ИИ для завершённого диалога не нужен. Ранее поддерживаемый явный заголовок завершения также распознаётся. Для уже завершённого диалога после обновления достаточно возобновить предмет.

В 0.2.1 устранено лишнее требование JSON-обёртки для текстовых диалогов: Coach запрашивает и принимает обычный ответ, включая кавычки, переносы строк и фрагменты кода. Корректная прежняя обёртка `{"reply":"..."}` также поддерживается; повреждённые обёртки, пустые/слишком длинные ответы, вызовы инструментов, отказы и незавершённые генерации не отправляются. Тесты с вариантами ответов по-прежнему требуют проверенный JSON с идентификаторами вариантов. Модель, ключ и предел токенов не меняются. После прежней ошибки обновите расширение и вкладку, затем нажмите «Повторить ИИ» в виджете Coach: это явно разрешает новый запрос и не повторяет уже отправленную реплику.

Обычный текст — стандартный формат Chat Completions согласно [OpenAI Docs](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create). Сам запрос и ответ HTTP API остаются JSON; убрана только необязательная дополнительная JSON-обёртка внутри текста сообщения модели. Исправление проверено с имитацией ответа `gpt-6-luna`, без платного обращения к API.

В 0.2.0 добавлены необязательные автоответы Coach и восстановление автоотправки уже выбранных ответов теста без нового запроса ИИ. Для включения откройте настройки ИИ: разрешите автоотправку тестов и отдельно автоответы Coach, сохраните и возобновите предмет. Существующие настройки автоматически не включаются. По умолчанию допускается до 12 автоответов на диалог; предел можно изменить от 1 до 30. После обновления API-ключ остаётся сохранённым, хотя поле ввода ключа намеренно пустое.

Версия 0.1.1 распознаёт адреса `assignment-submission`, кнопки Start/Resume assignment, вопросы в полноэкранном окне и Go to next item. Автоматический переход после теста требует явного сообщения Coursera об успешном завершении; одна отправка или наличие кнопки перехода не считаются завершением. Сломанная кнопка запуска не нажимается бесконечно.

Версия 0.1.2 ждёт загрузки вопросов до 20 секунд перед сообщением о неизвестном формате. Прерванный запрос ИИ после перезагрузки больше не остаётся в бесконечном ожидании: показывается причина и предлагается явный повтор. Кнопка «Повторить ИИ» может возобновить заблокированный тест, но не отменяет ручную паузу, расписание, лимит времени, число параллельных предметов или проверку смены аккаунта. Без нажатия повторный запрос не отправляется.

Версия 0.1.3 показывает потерю связи и привязки рабочей вкладки вместо исчезновения панели. Неответивший обработчик в уже загруженной вкладке останавливает только её предмет и предлагает обновление страницы; загружающиеся вкладки не блокируются преждевременно. «Продолжить» явно повторяет неудавшееся открытие задания, а очередной сигнал планировщика — нет. Диалоги Coach и интерактивные виджеты распознаются как отдельные материалы с понятным сообщением о ручной работе, без автоматической отправки сообщений или отметки завершения. Версия установленной панели видна внизу рядом с экспортом.

Проверка адреса сообщения использует текущий URL вкладки Chrome: исходный `sender.url` может сохраняться после навигации Coursera без полной перезагрузки. Проверки владельца вкладки, предмета, origin и точного текущего пути сохраняются; устаревший ответ ИИ после перехода на другой материал не применяется.

В версии 0.1.4 запросы к `https://api.openai.com/v1/chat/completions` используют `max_completion_tokens` с тем же настроенным пределом. Это современный параметр [официального API OpenAI](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create); `max_tokens` несовместим с некоторыми моделями. Для остальных совместимых серверов сохранён `max_tokens`. Бюджет не увеличивается автоматически. Ошибки API показывают только разрешённые диагностические коды и имена параметров, без тела ответа или ключа; неполный ответ из-за лимита токенов не вызывает платный повтор автоматически.

## Первый запуск

Добавьте одну из четырёх готовых программ или вставьте собственную ссылку Coursera. Откройте программу, проверьте распознанный список курсов. Курс можно добавить вручную через список предмета. Один отдельный курс не добавляется одновременно в разные предметы, чтобы часы не дублировались.

В настройках задайте рабочее окно и часовой пояс. По умолчанию: `Asia/Qyzylorda`, 09:00–21:00, четыре параллельных предмета. Нажмите «Запустить» у нужных предметов. Календарный отсчёт начинается после первой положительной записи активности; первый день считается днём 1, календарный минимум — дата начала + 24 дня.

В панели указан предварительный период подачи 2–9 ноября 2026 года. Даты можно изменить в настройках. Если прогноз окончания выходит за последний день подачи, появится предупреждение.

Суммарный дневной ориентир — 2 часа на предмет. Например, четыре курса по 10/15/10/15 часов вместе расходуют 50 часов. При пропусках оставшаяся нагрузка распределяется по оставшимся дням. Если рабочего окна недостаточно, прогноз окончания сдвигается. Расписание действует только при открытом Chrome и бодрствующем компьютере; после запуска браузера сохранённые планы восстанавливаются. Закрытие отдельной рабочей вкладки ставит её предмет на паузу.

## Что автоматизировано

- Независимые очереди предметов, календарное расписание, общий бюджет входящих курсов, пауза и восстановление.
- Обнаружение ссылок курсов и переходы по распознанным существующим ссылкам материалов.
- Воспроизведение стандартного HTML5-видео со скоростью 1× и переход к следующему материалу, если интерфейс его предоставляет.
- Необязательный ИИ для распознанных тестов с обычными radio/checkbox-полями. По умолчанию ответы выбираются для проверки. Автоматическая отправка — отдельная настройка.
- Необязательные текстовые ответы в поддерживаемом Coursera Coach: отдельная выключенная по умолчанию настройка, ограниченное число сообщений и переход только после явного завершения диалога.
- Локальный журнал и экспорт JSON с планом и фактически зарегистрированной активностью. Секрет API, ответы из кэша и идентификатор аккаунта в экспорт не входят.

Учёт видео основан на изменении позиции воспроизведения и ограниченном интервале реального времени. Перемотка, простой, длинные промежутки после сна и повторные события не создают часы. Чтение запускается кнопкой виджета на странице; учитывается только активная видимая вкладка с недавними действиями. Через 45 секунд без действий учёт чтения прекращается до следующего действия. Это измерение активности приложения, не подтверждение освоения материала.

У предмета три независимых показателя: часы, календарные дни и завершение обязательных курсов. 50 часов не завершают задания автоматически. Если обязательная работа закончилась раньше бюджета, понадобятся дополнительные материалы; пустое ожидание не создаёт часы. Если бюджет исчерпан до завершения заданий, автоматические действия остановятся, а оставшиеся задания будут видны в списке. Ожидание календарной даты не изменяет выданный Coursera сертификат или его дату.

## ИИ и отказоустойчивость

Укажите полный URL совместимого API `chat/completions`, название модели и при необходимости свой API-ключ. Поддерживается HTTPS либо локальный сервер через HTTP на `localhost`/`127.0.0.1`. При сохранении настроек Chrome запросит доступ только к выбранному серверу. Подписка на Coursera не включает доступ к стороннему API.

Ключ вводится только в отдельное поле, не в адрес сервера. URL с query-параметрами (`?…`), паролем или фрагментом (`#…`) не принимаются.

ИИ получает текст распознанного теста и варианты ответов. По умолчанию лимит — 40 запросов в календарный день и 800 токенов ответа. Вход ограничен по размеру. Кэш ограничен 60 ответами и 24 часами, разделён по предметам. При временной ошибке API или некорректном формате ответа допускаются два повтора, которые также расходуют дневной лимит. При 401/403 ИИ отключается до изменения настроек. Без API навигация, видео и расписания работают; задание, требующее ИИ, ставится на паузу. Другие предметы продолжают независимую работу.

Ответы ИИ проверяются по структуре и допустимым вариантам; правильность определяет Coursera. Повторная отправка одной и той же попытки автоматически не выполняется. Для известного Honor Code предусмотрена отдельная выключенная по умолчанию настройка. Другие заявления, идентификация, CAPTCHA и покупки требуют действий человека.

### Автоматическая отправка тестов и ответы Coach

В настройках ИИ доступны выключенные по умолчанию опции отправки тестов, ответов Coach и автогалочки Honor Code. Включение Coach не включает отправку тестов, и наоборот. Автогалочка применяется только при включённой автоотправке тестов. Общие настройки провайдера, дневной лимит запросов и лимит токенов применяются к обоим обработчикам; для самой галочки запрос ИИ не нужен.

Для поддерживаемого теста ИИ выбирает распознанные варианты. При включённой автоматической отправке расширение отправляет попытку один раз и ждёт явного сообщения об успешном результате; ожидание или одна отправка не считаются завершением. Только после подтверждённого успеха разрешён переход к следующему материалу. Поддерживаются одноразовое окно `Ready to submit?` и явно включённая галочка известного Honor Code. Остальные заявления, изменённые условия и проверка личности остаются ручными.

Обработчик Coach работает только с распознанным текстовым диалогом и его штатным полем сообщения. Он передаёт выбранному API-провайдеру текущий вопрос и до 6 последних пар «вопрос — ответ» с ограничением размера. Если в поле уже есть ваш черновик, расширение его не заменяет. После отправки оно ждёт нового сообщения Coach; одна и та же реплика повторно автоматически не отправляется. Явное завершение диалога разрешает переход дальше; наличие кнопки перехода само по себе не является подтверждением.

Параметр «Сообщений ИИ на диалог Coach» по умолчанию равен 12; допустимо целое число от 1 до 30. Достижение этого предела, неизвестная или блокирующая форма, запрос подтверждения, потеря связи или ошибка API останавливают автоматические действия для соответствующего предмета с пояснением. Другие предметы продолжают работу по своему расписанию. Лаборатории, произвольные встроенные виджеты и программные проекты этот обработчик не выполняет.

Изменение этих опций не требует повторного ввода сохранённого API-ключа: пустое поле сохраняет ключ; удалить его можно только явной опцией удаления.

API-ключ хранится локально в хранилище расширения с доступом только из доверенных контекстов расширения. Это не шифрованный сейф. Ключ не передаётся странице Coursera, не записывается в журнал и не включается в экспорт. Нет общего сервера, аналитики или общего ключа разработчика.

Пустое поле ключа при повторном открытии настроек — нормальное скрытие значения, а не его удаление. Если рядом указано «Ключ сохранён локально», повторный ввод не нужен. Обновление той же установленной копии сохраняет ключ, адрес и модель; это проверено отдельными тестами. Ключ удаляется только явной опцией удаления, удалением расширения или очисткой его данных. Другая папка распакованного расширения может создать отдельную копию с другим хранилищем.

## Границы текущей версии

Это первая рабочая версия расписания и браузерных обработчиков, а не проверенная гарантия получения всех четырёх сертификатов без участия. Внешние лаборатории, программные проекты, взаимная проверка, нестандартные тесты и неизвестная разметка останавливают соответствующий предмет с объяснением. Смена аккаунта обнаруживается, когда текущий профиль доступен в DOM; отдельный профиль Chrome на участника обязателен для разделения данных.

Публичные страницы и локальные тестовые страницы не заменяют проверку внутри оплаченного аккаунта. В подключённом Chrome проверены разметка и состояние открытых страниц Spot the Phish и Selenium Coach. После явного нажатия «Повторить ИИ» в 0.2.1 расширение отправило несколько реплик в Selenium Coach; Coursera выдала итоговую обратную связь и показала `Completed`. Обнаруженное зависание на этом экране исправлено в 0.2.2; переход к следующему уроку подтверждён в установленной версии. Переход после числового результата теста в 0.2.3 проверен локально и требует проверки установленного обновления. Успешное сквозное прохождение четырёх программ не подтверждено. При изменении интерфейса Coursera может потребоваться обновление обработчика. Иногда Chrome блокирует автовоспроизведение до ручного нажатия Play.

50 часов и 25 дней — заданные вами параметры планировщика. Они не означают одобрение комиссией: в приложенных силлабусах указаны 150 часов общей нагрузки, включая 50 часов лекций и практики; критерий признания и применение срока к отдельным курсам не подтверждены. Расширение не редактирует сертификаты, оценки или даты и не выдаёт собственный журнал за документ Coursera. Подготовка объединённого PDF сертификатов в эту версию не входит.

## Проверки и упаковка

Для разработки нужен Node.js 22+; установка npm-пакетов не требуется.

```powershell
npm test
npm run check
npm run package
```

Тесты покрывают общий бюджет предмета, параллельность, границы календаря, рабочее окно, восстановление, дубли/сон, проверку ответов ИИ и изоляцию сбоев. Браузерный smoke-тест использует Playwright, если он установлен отдельно:

```powershell
$env:PLAYWRIGHT_MODULE = 'C:\path\to\playwright'
$env:CHROME_EXECUTABLE = 'C:\path\to\chromium.exe'
node scripts/browser-smoke.mjs
node scripts/content-browser-smoke.mjs
node scripts/assignment-browser-smoke.mjs
```

Для проверки сохранённой разметки можно перед запуском `assignment-browser-smoke.mjs` задать `COURSERA_SAVED_HTML` — путь к локальному HTML задания. Из файла извлекается только разметка окна; его скрипты не исполняются. Ответы API имитируются, сетевые запросы перехватываются. Исходный HTML не включается в пакет расширения.

Автоматические тесты проверяют навигацию внутри страницы, потерю связи, таймауты, явный повтор, отбрасывание устаревших ответов ИИ, параметры OpenAI, сохранение API-настроек при обновлении, одноразовую отправку теста и ограниченный цикл Coach. В подключённом Chrome на локальных mock-страницах 0.2.0 проверены две текстовые реплики с переходом дальше, одна отправка теста с переходом после успешного результата, ожидание оценки без повторов, сохранение черновика, неподтверждённое заявление и отбрасывание ответа после отключения. Эти mock-проверки не используют внешний API или реальные задания. Для 0.2.2 добавлены регрессии наблюдаемого экрана завершения: переход без нового ИИ, отсутствие повторного запуска и отказ от перехода при неполных, скрытых или исторических признаках завершения.

Для повторения диагностики разработчиком доступен `npm run debug:browser`: локальный сервер отдаёт только тестовую страницу и код обработчика. На странице есть ссылки на сценарии задержки, прерванного запроса, потери привязки, отключения, ожидающего ответа ИИ, неработающей кнопки Resume, Coach и интерактивного виджета. Действия выполняются видимыми тестовыми кнопками, состояние и счётчики показываются под материалом. Внешний API и аккаунт Coursera не используются. Остановка сервера — Ctrl+C.

Для 0.2.2 в подключённом Chrome проверены локальные сценарии `coach-completed` (0 запросов ИИ, 1 переход, 0 повторных запусков), `coach-ended` (0 переходов без отметки Completed) и `coach-text` (2 текстовых ответа, затем 1 переход через новый экран завершения). Все 127 автоматических тестов и проверка синтаксиса прошли. Эти проверки не подменяют проверку установленного обновления на Coursera.

Для 0.2.3 прошли 133 автоматических теста. В Chrome на локальных страницах проверены проходная оценка (1 переход, 0 запросов ИИ), непроходная оценка и отсутствующий порог (0 переходов, 0 запросов ИИ). Именное подтверждение Honor Code осталось неотмеченным; после его ручной отметки на локальном стенде произошла одна отправка и один переход без повторного запроса ИИ.

В Chrome на локальной форме проверены 1 автогалочка, 1 отправка, 1 переход и отсутствие повторного запроса ИИ; при изменённом тексте соглашения — 0 автогалочек и 0 отправок.
